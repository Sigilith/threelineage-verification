# V1.1.0 Scenario Guide — Autonomy Under Pressure

Status: V1.1.0 release candidate workstream; not a published release.

## Purpose

This deterministic scenario exercises the existing ThreeLineage verification components together to test whether permitted authority reduces as operating conditions deteriorate, and whether delegation, replay and evidence-integrity controls remain effective.

The scenario uses synthetic, normalized telemetry and simulated setpoint proposals. It is not connected to physical equipment.

## Component path

```text
Synthetic OT telemetry + proposed delta
                 |
                 v
       Non-actuating OT adapter
                 |
                 v
      Sigilith autonomy evaluation <----- verified delegation alpha cap
                 |
          governance verdict
                 |
                 v
       Guardian single-use permit
                 |
                 v
        TraceGuard evidence ledger
```

The delegation verifier is exercised separately to produce a verified authority context and effective alpha cap. The scenario then passes that cap into the Sigilith evaluation. The tests do not claim that this repository contains a complete live OT orchestration service.

## Run the scenario

From the repository root, install the declared dependencies and run:

```bash
python -m pip install -r requirements.txt
python -m pytest -q tests/test_autonomy_under_pressure_scenario.py
```

Run the complete regression and adversarial release gate with:

```bash
bash scripts/run_release_gate.sh
```

## Deterministic scenario sequence

| Case | Synthetic input | Expected result |
|---|---|---|
| Nominal | state 0.46; delta +0.02 | PERMIT_FULL; permitted delta +0.02 |
| Rising pressure | state 0.78; delta +0.04; recent deltas +0.02, +0.02 | PERMIT_ATTENUATED; alpha below 1; delta clamped proportionally |
| Converging drift | state 0.80; delta +0.04; six recent deltas +0.04 | HOLD_ESCALATE; zero permitted delta |
| Hard boundary | state 0.90; delta +0.01 | FAIL_CLOSED; zero permitted delta |
| Invalid quality | quality_good false | FAIL_CLOSED; zero clamped delta |

For the rising-pressure case, the current implementation produces alpha 0.552 and a permitted delta of 0.02208. Tests assert the proportional relationship as well as the verdict and reduced magnitude.

## Delegation, replay and evidence

- A valid two-hop Ed25519 delegation chain narrows the alpha cap from 0.75 to 0.60. A nominal proposal of +0.02 is therefore limited to +0.012.
- A child delegation attempting to increase a parent cap from 0.50 to 0.80 is rejected.
- Guardian accepts a single-use nonce once and rejects a second consumption attempt.
- TraceGuard reload verifies the clean local hash chain and rejects a record whose permitted delta has been altered without a matching hash.

## TraceGuard and TICP-1 integrity boundary

The TraceGuard implementation exercised by this repository is a local SHA-256 hash-chained ledger. It validates sequence, previous-hash links and record hashes. This detects record modification when the historical chain is not coherently rewritten; the local chain alone does not prevent a privileged host attacker from rewriting the complete ledger and locally trusted state.

ThreeLineage has separately developed TICP-1, a checkpoint-integrity protocol using domain-separated SHA-256 checkpoint hashes, detached Ed25519 signatures, previous-checkpoint linkage, sequence continuity and support for external anchor receipts. The recorded local implementation has a reported 18/18 passing tests. This is historical local test evidence, not an independently assessed result and not a test run in this repository.

Independent signing infrastructure, a live externally maintained rollback-resistant anchor and integration into this V1.1.0 execution-verification path have not yet been demonstrated. Do not describe TICP-1 as providing deployed protection against full host compromise until those elements are independently implemented and verified.

## Interpreting the OT adapter output

The adapter's `actuation_permitted` field is a governance eligibility result for the candidate proposal. The adapter is explicitly non-actuating: it does not write to OPC-UA, DNP3, IEC-61850, a PLC, an RTU, a breaker or any physical device. A permitted candidate is not evidence that a physical action occurred.

## Assurance boundary

This is a deterministic software test using synthetic inputs. It is not a live OT integration, physical actuation test, hardware SIS validation, safety case, penetration test, independent security assessment, IEC 62443 certification or proof of safe operation in a real industrial process.
